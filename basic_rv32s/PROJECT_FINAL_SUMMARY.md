## 🔴 发现的核心问题

### Bug：流水线跳转指令丢失

**现象**：

```
执行序列：
PC=0x24: jal main (跳到 0x2c)
PC=0x2c: lui a4,0x10010  ← 被跳过！
PC=0x30: addi a4,a4,4    ← 直接执行这条

寄存器写回：
[3135000] WB: PC=00000024, rd=x1, data=00000028  ✅ JAL
[3175000] WB: PC=00000030, rd=x14, data=00000004  ❌ ADDI (LUI被跳过)
```

**根本原因**：

**5 级流水线的经典问题 - 跳转延迟槽**

当跳转指令在 EX 阶段执行时：
- IF 阶段：PC+4 (错误指令)
- ID 阶段：PC+8 (错误指令)

流水线冲刷逻辑：
```verilog
if (trap_done && (branch_prediction_miss || EX_jump)) begin
    IF_ID_flush = 1'b1;  // 冲刷 IF→ID
    ID_EX_flush = 1'b1;  // 冲刷 ID→EX
end
```

**时序问题**：
1. JAL 在 EX 阶段跳转到 0x2c
2. LUI 已经在 IF 阶段被正确取指
3. **冲刷逻辑错误地把 LUI 也冲刷掉了**
4. ADDI 被重新取指并执行

**影响**：
- 所有使用 LUI 的程序失败
- 所有使用大立即数的代码失败
- RT-Thread 无法运行

## 🔧 尝试的修复方案

### 方案 A：ID 阶段跳转（部分实施）

**思路**：将 JAL/JALR 的跳转判断提前到 ID 阶段

**实施内容**：
1. ✅ 修改 `PC_Controller` - 添加 ID_jump 和 ID_jump_target
2. ✅ 添加 ID 阶段跳转逻辑计算
3. ✅ 修改 `Hazard_Unit` - 简化冲刷逻辑
4. ✅ 编译成功

**遇到的新问题**：

**分支指令也在 EX 阶段执行！**

```
PC=0x14: beq t0,t1,24  → 在 EX 阶段跳转
PC=0x24: jal 2c <main> → 被冲刷，没有进入 ID 阶段！
```

调试输出显示：
- PC=0x24 的 JAL 从未进入 ID 阶段
- 只检测到 PC=0x28 的 j 指令（死循环）

**结论**：方案 A 需要同时处理分支和跳转，工作量远超预期

---

## 📋 方案 A 的完整需求

要彻底修复，需要：

1. **将所有控制流指令提前到 ID 阶段**：
   - JAL/JALR
   - BEQ/BNE/BLT/BGE/BLTU/BGEU
   
2. **修改数据通路**：
   - ID 阶段需要能够读取寄存器（JALR, 分支比较）
   - ID 阶段需要比较器（分支判断）
   - ID 阶段需要加法器（地址计算）

3. **处理数据冒险**：
   - 分支指令的 rs1/rs2 如果依赖前面指令，需要前递或停顿

4. **重新设计冲刷逻辑**：
   - ID 阶段跳转：只冲刷 IF
   - EX 阶段跳转（异常）：冲刷 IF + ID

**工作量**：这是一个系统性的CPU重构项目
