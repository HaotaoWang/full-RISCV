- **复位功能**: ✅ 正常（按 K1 灯灭，松开灯亮）

## 🔧 解决步骤

### 步骤 1: 正确配置 PuTTY ⭐

**重要**：必须使用 **COM5**

**完整配置**：
```
Connection type: Serial
Serial line: COM5          ⭐ 不是 COM3/4/6/7
Speed: 115200
```

**高级设置**（点击 Serial）：
```
Data bits: 8
Stop bits: 1
Parity: None
Flow control: None
```

**保存配置**：
1. 在 Session 中输入名称：`FPGA_COM5`
2. 点击 **Save**
3. 下次直接双击加载

---

### 步骤 2: 测试串口

**在 PuTTY 中测试**：
1. 打开 COM5
2. 按 K1 复位
3. 观察是否有任何字符（即使是乱码）

**如果有乱码**：
- 说明串口连接正常，但波特率错误
- 尝试其他波特率：9600, 38400, 57600

**如果完全没有输出**：
- 继续下面的排查

---

### 步骤 3: 检查程序是否正在运行

**观察 LED 行为**：

**情况 A**：LED 持续全亮
- 可能程序卡在初始化阶段
- 或者在等待某些条件

**情况 B**：LED 有规律闪烁
- 说明程序正在运行
- 可能串口未配置或输出被禁用

**情况 C**：LED 无规律变化
- 说明程序在执行但可能有问题

**你的情况**：LED 全亮 + 复位功能正常
- ✅ 硬件工作
- ❓ 程序可能卡住或串口未配置

---

### 步骤 4: 检查 RT-Thread 配置

**可能的问题**：
1. RT-Thread 的串口输出被禁用
2. 波特率配置错误
3. 串口引脚未正确连接

**检查方法**：
查看 RT-Thread 的配置文件（如果有的话）

---

### 步骤 5: 使用其他串口工具测试

**尝试其他工具**（排除 PuTTY 问题）：

**方法 A: 使用 PowerShell**
```powershell
# 打开串口
$port = new-Object System.IO.Ports.SerialPort COM5,115200,None,8,one
$port.Open()

# 读取数据（持续监控）
while($true) {
    if($port.BytesToRead -gt 0) {
        $port.ReadExisting()
    }
    Start-Sleep -Milliseconds 100
}

# 关闭（按 Ctrl+C 停止后执行）
$port.Close()
```

**方法 B: 使用 Python**
```python
import serial
import time

ser = serial.Serial('COM5', 115200, timeout=1)
print("Listening on COM5...")

while True:
    if ser.in_waiting > 0:
        data = ser.read(ser.in_waiting)
        print(data.decode('utf-8', errors='ignore'), end='')
    time.sleep(0.1)
```

### 步骤 6: 检查硬件连接

**确认 UART 引脚连接**：

1. **查看板子文档**：确认哪个 USB 口是串口
2. **检查连接**：
   - USB 线是否插好
   - 是否插对了接口（有些板子有多个 USB 口）

3. **尝试重新插拔**：
   - 拔出 USB 线
   - 重新插入
   - 检查设备管理器中 COM5 是否还在

## 🔍 深入排查

### 如果以上都不行

**问题可能在于**：

#### 1. 程序本身有问题

**症状**：
- 硬件正常（LED 能控制）
- 但程序逻辑可能卡住

**可能原因**：
- JALR 修复后仍有问题
- 初始化过程卡住
- 等待某些条件

**验证方法**：
- 使用 Vivado Hardware Manager
- 添加 ILA 调试
- 查看 PC 值

#### 2. 串口硬件未配置

**症状**：
- 程序运行正常
- 但串口硬件未初始化

**可能原因**：
- Vivado 工程中 UART IP 核未配置
- 引脚约束错误
- 时钟未连接

**验证方法**：
查看 Vivado 工程中的 UART 模块配置

#### 3. RT-Thread 未启动

**症状**：
- 程序在 RT-Thread 之前就卡住了
- 串口输出还没执行到

**可能原因**：
- JALR 问题导致初始化失败
- 内存初始化问题
