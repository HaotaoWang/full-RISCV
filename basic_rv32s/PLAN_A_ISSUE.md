# 方案 A 实施遇到的问题

## 发现

ID 阶段跳转逻辑已实现，但测试结果显示：

1. ✅ ID_jump 信号能够生成
2. ❌ **PC=0x24 的 JAL 指令没有进入 ID 阶段！**
3. ❌ **PC=0x2c 的 LUI 指令仍然被跳过**

## 调试输出

```
[3105000] JAL_DECODE: pc=00000028, ID_jump=1, target=00000030, imm=00000008
[3135000] WB: PC=00000024, rd=x1, data=00000028
```

**只检测到 PC=0x28 的指令（死循环 j 28），没有检测到 PC=0x24 的 JAL！**

## 根本问题

方案 A 的假设是：**JAL 指令会正常进入 ID 阶段**

但实际情况是：**流水线中存在其他机制（可能是分支预测器或取指逻辑）在 JAL 到达 ID 阶段之前就改变了 PC，导致 JAL 指令被跳过！**

## 结论

方案 A 需要更深入的修改，包括：
1. 确保 JAL 指令能够正常进入 ID 阶段
2. 可能需要修改分支预测器
3. 可能需要修改取指逻辑

这比预期的要复杂得多。

## 建议

由于时间和复杂度的原因，建议：
1. 暂时保留原有的 EX 阶段跳转逻辑
2. 重新审视整个流水线控制设计
3. 或者采用更简单的方案（如使用分支预测器正确预测 JAL）

当前的 CPU 设计存在深层次的流水线控制问题，需要系统性的重构才能彻底解决。
