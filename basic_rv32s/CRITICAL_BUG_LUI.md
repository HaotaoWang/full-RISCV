# 🔴 紧急：发现 CPU 严重 Bug - LUI 指令失败

## 问题描述

**寄存器 a4 的高位全部丢失！**

### 执行轨迹

```asm
PC=0x2c:  lui  a4,0x10010    # 应设置 a4 = 0x10010000
PC=0x30:  addi a4,a4,4       # 应设置 a4 = 0x10010004
PC=0x38:  lw   a5,0(a4)      # 应从 0x10010004 加载
```

### 实际寄存器值

```
[3165000] PC=30 (addi): a4(x14)=00000000, MEM_alu=00000004
[3345000] PC=38 (lw):   a4(x14)=00000004, MEM_alu=00000004
```

**分析**：
- PC=0x30 时，a4 = `0x00000000`（应该是 `0x10010000`）← LUI 失败！
- PC=0x38 时，a4 = `0x00000004`（应该是 `0x10010004`）

**结论**：LUI 指令完全没有生效，高20位全部丢失。

---

## 为什么 test_noio.c 能正常运行？

让我检查 test_noio.c 是否使用了 LUI 指令...

查看 test_noio.elf 的反汇编：
```asm
2c:	ff010113    addi sp,sp,-16
30:	00012623    sw zero,12(sp)
34:	00100793    li a5,1         # 立即数加载
38:	00f12423    sw a5,8(sp)
3c:	00812703    lw a4,8(sp)
40:	00a00793    li a5,10
```

**test_noio.c 只使用了小立即数（`li` 伪指令），没有使用 LUI！**

`li a5,10` 被编译为 `addi a5,x0,10`，不需要 LUI。

---

## 根本原因

**LUI 指令在 CPU 中未正确实现或写回路径有问题。**

可能的原因：
1. **写回数据选择器错误** - LUI 的结果没有被正确选择
2. **寄存器文件写使能问题** - LUI 执行时寄存器写使能未激活
3. **LUI 结果计算错误** - ALU 或立即数生成器有问题

---

## 验证方法

创建一个只测试 LUI 的程序：

```c
int main(void) {
    volatile int x = 0x12345000;  // 强制使用 LUI
    if (x == 0x12345000) {
        while(1);  // 成功
    } else {
        while(1);  // 失败
    }
}
```
